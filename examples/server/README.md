# MoorAI in server mode

For agents that run without a developer's laptop: `claude -p` in CI, the Claude Code GitHub Action, an Agent
SDK service in a container. The Agent SDK runs "shell command hooks from settings files when the
corresponding `settingSources` … entry is enabled, which it is for default `query()` options"
([Agent SDK hooks](https://code.claude.com/docs/en/agent-sdk/hooks)), so MoorAI's hook runs there unchanged.
Content stays in your process and your infrastructure; the console receives content-free signals only.

| File | What it is |
|---|---|
| [`Dockerfile`](Dockerfile) | Node, Claude Code and MoorAI, with the hooks in Claude Code's managed settings and `MOORAI_MODE=server`. |
| [`github-actions.yml`](github-actions.yml) | A workflow that runs `claude -p` on a GitHub-hosted runner with MoorAI. |
| [`managed-settings.mjs`](managed-settings.mjs) | Writes MoorAI's hook registration into a managed settings file, generated by MoorAI's own installer. |

## What server mode changes

Server mode is on when the root-owned `/etc/moorai/config.json` says `"mode": "server"` or the environment
sets `MOORAI_MODE=server`. With it off, the hook behaves exactly as on a laptop.

- **Configuration.** `MOORAI_SERVER_URL`, `MOORAI_TENANT` and `MOORAI_INSTALL_TOKEN` come from the
  root-owned system file first, then the environment, then `~/.moorai/config.json`. A `MOORAI_*` value that a
  user, project or local Claude Code settings file sets in its `env` block is refused and reported as
  tampering, because a repository's `.claude/settings.json` can set the hook's environment.
- **"Ask" has no one to answer it.** A decision that would ask a human is denied, with a reason saying no
  approver exists. An org policy (or the system file) can choose `allow-with-report` instead; the
  environment can only choose `deny`.
- **Identity is the workload.** `MOORAI_SERVICE_ID` names it; on GitHub Actions without it, the name is
  `github:<repository>:<workflow>:<job>`. It is hashed into the actor exactly like `user@host` on a laptop, so every
  deploy and every run of the same job reports as one workload.
- **Enforcement without a laptop.** Server mode enforces policy even before a token is set; there is no
  developer to coach.
- **Doctor.** `moorai-doctor` shows where each setting came from (the token as a fingerprint), the
  headless-ask mapping, the service identity, and any refused settings-file value.

The desktop app, the AI bill of materials, shadow-AI inventory and OS posture do not apply on a server.
